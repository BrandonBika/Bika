=====================================================================
BUILD PROMPT — CivicNeuro resident app: "Beacon" tab (bottom nav)
=====================================================================

ROLE
You are a senior mobile front-end engineer. Build the Beacon tab of the
CivicNeuro resident app exactly as specified below. Everything here was
taken from the approved screen flow map (v7), so treat every number,
colour and string as the source of truth. Where this document says
"ASSUMPTION", it is a sensible default the designers did not draw;
implement it, but keep it easy to change.

Beacon = live location sharing between people who have accepted each
other into a private "circle" (family, friends). It is a safety feature:
"I'm walking home, watch my progress." It replaced the old bottom-nav
"Profile" tab.

Stack: not fixed. Implement in the project's existing stack. All sizes
are logical px on a 300px-wide screen (the width the mockups were drawn
at). Layouts must flex to real device widths (320–430px); never hard-code
300px widths. Padding, radii, font sizes and colours stay as given.

Companion files: beacon-tab-layout-map.html (annotated anatomy + screen
flow). Use it as the visual reference.

Screen letters used below: A Beacon main · A2 Share mode chooser · A3 Draw
your path · A4 Start sharing confirm · B Add to circle · C Chat ·
D Live session · D2 Off-path alert · E Contacts explainer · F OS prompt ·
G Find from contacts · H Contacts denied.

SCOPE
In scope:
  1. Beacon main screen (live map, bottom sheet, tabs, member list)
  2. Add to your circle (search, send request, accept/decline)
  3. Chat with a circle member
  4. Share mode chooser: share live location OR draw a path (NEW)
  5. Draw your path (NEW)
  6. Start sharing confirm: members, duration, off-path alert (NEW)
  7. Live session, plus its off-path alert state (NEW)
  8. Shared contacts permission flow (explainer, OS prompt, denied)
  9. "Find from my contacts" list
Out of scope (stub the navigation): Home, Lifeline, Reports, Alerts,
Menu contents, the Lifeline side of the contacts permission (picker/card).

3c. SCREEN A3 — DRAW YOUR PATH (NEW)
---------------------------------------------------------------------
Full-screen map. Bottom nav and Menu button are HIDDEN (same as the live
session). Map layer identical to Beacon main (sage base, soft teal glows,
street grid / real map in a muted light style).
Floating top controls (absolute, top 12, left 12, right 12, flex, gap 8,
  align center, justify flex-start):
    Back button: 32x32 circle, bg #FFF, shadow 0 8px 18px
      rgba(22,36,31,.16), chevron-left 14px.
    Title pill: bg #FFF, radius 99, padding 8px 14px, 13px/700, shadow
      0 8px 18px rgba(22,36,31,.16), pencil icon 13px --beacon, gap 6:
      "Draw your path".
Hint / summary card (absolute, top 56, left 12, right 12): bg #FFF,
  radius 12, padding 9px 12px, shadow 0 8px 18px rgba(22,36,31,.14).
    Title 11.5px/700, body 10.5px ink-soft, line-height 1.45, margin-top 2.
    States:
      Idle: title "Draw your path"; body "Drag your finger from where you
        are to where you are going. Lift to finish."
      Drawing: title shows live distance, e.g. "0.9 km so far".
      Drawn: title "Path drawn · 1.4 km · about 18 min"; body "Drag your
        finger from where you are to where you are going. Lift to
        finish. The shaded strip is the alert zone." (the body may be
        shortened once a path exists — ASSUMPTION)
Path
  Line: solid, stroke --beacon, width 4, round caps and joins.
  Alert zone: the same path stroked rgba(28,140,153,.16), width 34 in the
    mockup. In production draw it as a corridor of 100 m on each side
    (200 m total) and scale it with the map zoom so it always matches the
    real ground distance.
  Start dot: 12x12 circle --beacon, 3px #FFF ring, shadow
    0 3px 8px rgba(22,36,31,.3), at the user's current position, with a
    label under it: "You are here" — bg #FFF, radius 99, padding 3px 9px,
    9.5px/700, shadow 0 4px 10px rgba(22,36,31,.16).
  Destination pin: 32px teal map pin (fill --beacon, white inner circle),
    dropped at the end of the stroke when the finger lifts.
Toolbar (absolute, left 12, right 12, bottom 14 + safe-area): bg #FFF,
  radius 16, padding 10, shadow 0 14px 30px rgba(22,36,31,.2).
    Legend row: 10px ink-soft, gap 7, margin 0 2px 9px — a 22x10 pill
      swatch rgba(28,140,153,.25) then "Alert zone · 100 m either side of
      your path".
    Button row, gap 8, three equal buttons (flex 1, 11px/700, padding
      9px 6px, radius 10, border 1px --line, bg #FFF, text --ink, icon
      12px + label):
        "Undo" (undo icon), "Clear" (trash icon), and "Next" (bg --beacon,
        border --beacon, text white, no icon).
Behaviour
  - One finger draws, two fingers pan/zoom the map.
  - The path must start at (or within ~30 m of) the current position; if
    the first touch is farther away, snap the start to the current
    position and show a brief toast (ASSUMPTION).
  - Lifting the finger ends the stroke and drops the destination pin.
    Touching and dragging from the pin extends the path (ASSUMPTION:
    single continuous path, no separate branches).
  - Smooth and simplify the points (ASSUMPTION: Douglas–Peucker, ~5 m
    tolerance, and cap to ~500 points). Optional "snap to roads" is out of
    scope unless product asks for it.
  - Distance and time update live (walking speed ~4.5 km/h, ASSUMPTION).
    Minimum path length 100 m; maximum 10 km (ASSUMPTION).
  - Undo removes the last stroke segment. Clear removes the whole path
    after a confirm. Next is disabled until a path with a destination
    exists; Undo and Clear are disabled while the map is empty.
  - Back with a drawn path: confirm dialog (Withdraw-dialog geometry),
    title "Discard your path?", buttons "Keep drawing" (ghost) and
    "Discard" (danger red #A32D2D). Without a path, Back goes straight to
    A2.
  - Accessibility alternative (REQUIRED): drawing is not usable with a
    screen reader or switch control, so provide "Set destination instead"
    (search for a place or tap the map) that generates the path from a
    route service. It uses the same Confirm screen afterwards.
  - Next -> Start sharing confirm (A4).

13. PRIVACY, SAFETY, ACCESSIBILITY, QUALITY BAR
---------------------------------------------------------------------
- Sharing is opt-in per session, to accepted members only; always show a
  visible "you are sharing" indicator (session card / OS indicator).
- Never share location in the background outside an active session.
- The drawn path and off-path events are visible only to the members
  selected for that session and are deleted with the session summary
  (ASSUMPTION — confirm retention with privacy/legal).
- Contacts: ask once, hashed matching, never store unmatched contacts,
  everything works without the permission.
- Search results only include discoverable profiles; do not reveal phone
  numbers or exact addresses in results (ward only).
- Tap targets >= 44x44 even where the visual is smaller (back 26px,
  message button 28px, add button 32px, tabs, pills).
- Don't rely on colour alone: live state also uses text ("Sharing") and
  the badge shape; Accept/Decline carry text labels.
- Contrast: do not lighten ink-soft or the --beacon-deep text; white text
  on --beacon (#1C8C99) is acceptable for 12px+ bold labels only.
- Screen-reader labels: live pin "Thabo, sharing live location, 6
  minutes away"; (+) "Add to your circle"; message button "Message
  Thabo"; Stop sharing announced as destructive.
- Support font scaling to 130% without clipping; bottom sheet grows,
  pills stay one line.
- Respect reduced motion (no pulsing pins; sheet slide only).
- Sheet slide ~250ms ease-out; dialogs fade/scale from .96 in ~150ms.
- Offline: keep the last known positions with a "Last updated <time>"
  note; queue chat messages and requests and retry; block starting a new
  session without a connection with the shared error pattern.
- Battery: adaptive location update rate (faster when moving, slower
  when still), stop updates immediately when the session ends.
