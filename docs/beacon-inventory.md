### Original user flow to a share

1. Resident taps **Beacon** in the bottom navigation. The original route is `beacon-home`, not the safety page. Opening the home page immediately checks geolocation permission and starts a location watch; it can display its own location prompt. Sources: [`bottom-nav.js`](../apps/resident-pwa/src/components/bottom-nav/bottom-nav.js), [`router.js`](../apps/resident-pwa/src/router.js), [`beacon-home.js`](../apps/resident-pwa/src/pages/beacon-home/beacon-home.js).
2. The resident can select **Share my live location**, then choose **Share live location** or **Draw a path**. A route can be drawn manually or a destination can be searched; a non-mock route is required before continuing. Sources: [`beacon-home.js`](../apps/resident-pwa/src/pages/beacon-home/beacon-home.js), [`beacon-draw-path.js`](../apps/resident-pwa/src/pages/beacon-draw-path/beacon-draw-path.js).
3. On confirmation, user selects one or more circle members, duration, and off-path-alert preference, then starts. Path sharing requires GPS validation against the route start. Start requires at least one member. Sources: [`beacon-start-confirm.js`](../apps/resident-pwa/src/pages/beacon-start-confirm/beacon-start-confirm.js), [`beacon-location.js`](../apps/resident-pwa/src/features/beacon/beacon-location.js).
4. If the resident has no circle member, the UI routes to Add to circle. The default circle is empty; resident search returns `[]`; saving a phone contact does not create a member; Invite only prepares an SMS. Thus, in a fresh normal account, there is no supported way in this build to populate a share recipient and the Start button cannot become enabled. Local state can display previously saved/custom state, but that is not server-delivered membership. Sources: [`beacon.client.js`](../apps/resident-pwa/src/features/beacon/beacon.client.js), [`beacon-add-to-circle.js`](../apps/resident-pwa/src/pages/beacon-add-to-circle/beacon-add-to-circle.js), [`beacon-find-contacts.js`](../apps/resident-pwa/src/pages/beacon-find-contacts/beacon-find-contacts.js), [`beacon-start-confirm.js`](../apps/resident-pwa/src/pages/beacon-start-confirm/beacon-start-confirm.js).
5. If a session is locally constructed, the active page watches GPS and updates its own map. It does not send location points or share the map with a selected person. Details are in sections 4 and 6. Sources: [`beacon-share-session.js`](../apps/resident-pwa/src/pages/beacon-share-session/beacon-share-session.js), [`beacon.client.js`](../apps/resident-pwa/src/features/beacon/beacon.client.js).

The existing route definitions remain, but the app shell receives the notice page instead. Lifeline routes are not caught by this rule. Sources: current diff to [`router.js`](../apps/resident-pwa/src/router.js), route table in [`router.js`](../apps/resident-pwa/src/router.js).

These source modules have not been deleted. Source: [`router.js`](../apps/resident-pwa/src/router.js) and the page files listed in the table above.

## 3. Contacts and invites

### Device contact selection and upload

- Beacon offers both device picker and manual entry. It requests exactly the `name` and `tel` fields, with `multiple: true`; if either is an array it takes **only the first name and first phone number**. It discards selections without a nonblank name and valid-length phone. Lifeline uses the same two fields and first-value behavior, but its phone-length threshold is 3–15 digits, unlike Beacon’s 7–15. Sources: [`beacon-find-contacts.js`](../apps/resident-pwa/src/pages/beacon-find-contacts/beacon-find-contacts.js), [`lifeline-contacts.js`](../apps/resident-pwa/src/features/lifeline/lifeline-contacts.js).
- There is no whole-address-book upload. Beacon sends the explicitly selected/typed `name` and `phone` to Supabase only when the user adds/saves them. It sends only those selected records, not email, address, photo, or the rest of the contact object. The client performs an upsert by account owner and normalized phone. Sources: [`beacon-find-contacts.js`](../apps/resident-pwa/src/pages/beacon-find-contacts/beacon-find-contacts.js), [`packages/supabase-client/src/beacon-contacts.js`](../packages/supabase-client/src/beacon-contacts.js).
- The picker is available only when `navigator.contacts.select` exists; otherwise the screen retains manual name/number entry. The page catches non-cancel errors and presents manual-entry guidance. The code does not enumerate browsers. Sources: [`beacon-find-contacts.js`](../apps/resident-pwa/src/pages/beacon-find-contacts/beacon-find-contacts.js), [`lifeline-contacts.js`](../apps/resident-pwa/src/features/lifeline/lifeline-contacts.js).
- Lifeline contact picks remain in the current form until the user saves a group. Saving sends the member names/phones in `members` JSONB to `lifeline_cards`; it does not write to `beacon_contacts`. Sources: [`lifeline-card-create.js`](../apps/resident-pwa/src/pages/lifeline-card-create/lifeline-card-create.js), [`lifeline-cards.js`](../packages/supabase-client/src/lifeline-cards.js).

### Beacon phone normalization and validation

1. UI `normalizePhone()` trims outer whitespace, removes all non-digits, and re-adds one leading `+` only if the original trimmed string started with `+`. `isValidPhone()` strips punctuation again and accepts 7–15 digits. Sources: [`beacon-find-contacts.js`](../apps/resident-pwa/src/pages/beacon-find-contacts/beacon-find-contacts.js).
2. The Supabase client trims the submitted raw phone, stores it in `phone`, and sets `phone_normalized` to **digits only** (`phone.replace(/\D/g, '')`). It rejects blank name, name over 100 characters, or fewer than 7 / more than 15 digits. The database independently enforces `phone_normalized ~ '^[0-9]{7,15}$'` and name length 1–100. Sources: [`beacon-contacts.js`](../packages/supabase-client/src/beacon-contacts.js), [`0029_beacon_contacts.sql`](../supabase/migrations/0029_beacon_contacts.sql).
3. There is no country-aware parsing or South African normalization. `+27 82...` normalizes to digits beginning `27`; `082...` stays digits beginning `0`. They do **not** normalize to the same number and can be saved twice. A number such as `031...` is preserved as entered in `phone`, with digits in `phone_normalized`. Any punctuation/letters are stripped for validation/normalized uniqueness rather than semantically interpreted. Numbers with 7–15 digits, including international-prefix-like `00...`, pass the digit-count check. Sources: [`beacon-find-contacts.js`](../apps/resident-pwa/src/pages/beacon-find-contacts/beacon-find-contacts.js), [`beacon-contacts.js`](../packages/supabase-client/src/beacon-contacts.js), [`0029_beacon_contacts.sql`](../supabase/migrations/0029_beacon_contacts.sql).
4. Client de-duplication and database uniqueness are owner + digits-only number; saving an existing normalized phone merges/upserts the row. No phone-number ownership verification is performed. Sources: [`beacon-find-contacts.js`](../apps/resident-pwa/src/pages/beacon-find-contacts/beacon-find-contacts.js), [`beacon-contacts.js`](../packages/supabase-client/src/beacon-contacts.js), [`0029_beacon_contacts.sql`](../supabase/migrations/0029_beacon_contacts.sql).

### What Invite does

- The button constructs `new URL('#register', window.location.href)`, then message text **“Join me on CivicNeuro: {registration URL}”**. It updates the contact first: `invitation_status = 'message_prepared'`, `message_prepared_at = new Date().toISOString()`. It then navigates to `sms:{normalized phone}?body={encoded message}`. Sources: [`beacon-find-contacts.js`](../apps/resident-pwa/src/pages/beacon-find-contacts/beacon-find-contacts.js), [`beacon-contacts.js`](../packages/supabase-client/src/beacon-contacts.js), [`0029_beacon_contacts.sql`](../supabase/migrations/0029_beacon_contacts.sql).
- This is **the user's device SMS handler**, not a server send, WhatsApp deep link, or Web Share API. User may still have to press Send. The timestamp means the app prepared a message/opened the SMS URI; it does not prove the SMS app opened, message was sent/delivered, the recipient registered, or a circle request was accepted. `invitation_status` has only `saved` and `message_prepared`. Sources: [`beacon-find-contacts.js`](../apps/resident-pwa/src/pages/beacon-find-contacts/beacon-find-contacts.js), [`0029_beacon_contacts.sql`](../supabase/migrations/0029_beacon_contacts.sql).
- A recipient without the app gets a normal `#register` web URL if it opens. There is no invite token, contact-to-account binding, automatic account matching, or acceptance flow in the link. A join alone therefore does not add them to the inviter’s circle. Sources: [`beacon-find-contacts.js`](../apps/resident-pwa/src/pages/beacon-find-contacts/beacon-find-contacts.js), [`router.js`](../apps/resident-pwa/src/router.js), [`beacon.client.js`](../apps/resident-pwa/src/features/beacon/beacon.client.js).
- There is no match from `beacon_contacts.phone_normalized` to `resident_profiles.phone` or `profiles.phone`. `searchResidents()` lowercases/validates a query and then unconditionally returns `[]`; it does not call `BEACON_SEARCH`, `BEACON_MEMBERS`, or query Supabase profiles. Thus there is currently no account-existence exposure through that search implementation. Sources: [`beacon.client.js`](../apps/resident-pwa/src/features/beacon/beacon.client.js), [`beacon-add-to-circle.js`](../apps/resident-pwa/src/pages/beacon-add-to-circle/beacon-add-to-circle.js), [`endpoints.js`](../packages/functions-client/src/endpoints.js).

## 6. Live location and route behavior

- **Position capture:** `watchPosition` is used with `enableHighAccuracy: true`, `maximumAge: 0`, and a 30-second timeout. The home page asks for location on entry, before a share is started; the active-session page starts a fresh watch when mounted. A first reading below 50 m is “precise”; a reading from 50 m through 150 m is reduced and requires confirmation; worse than 150 m cannot start. Network/IP-like readings above 5,000 m are treated as unusable. Sources: [`beacon-location.js`](../apps/resident-pwa/src/features/beacon/beacon-location.js), [`beacon-home.js`](../apps/resident-pwa/src/pages/beacon-home/beacon-home.js), [`beacon-start-confirm.js`](../apps/resident-pwa/src/pages/beacon-start-confirm/beacon-start-confirm.js).
- **Transmission:** GPS fixes update the local map and local off-path/arrival logic. They are not POSTed to a Beacon endpoint or inserted into `beacon_location_points`; the active page imports no such writer. Place searches send search text to `beacon-route` and its geocoder; route requests send origin/destination coordinates to `beacon-route` and its routing service. Map tile requests go to the configured tile host. Sources: [`beacon-share-session.js`](../apps/resident-pwa/src/pages/beacon-share-session/beacon-share-session.js), [`beacon.client.js`](../apps/resident-pwa/src/features/beacon/beacon.client.js), [`beacon-route/handler.js`](../supabase/functions/beacon-route/handler.js), [`leaflet-map.js`](../apps/resident-pwa/src/features/beacon/leaflet-map.js).
- **Tab close/background/lock:** there is no background location service, service-worker GPS process, or remote uploader. Page disconnection calls `clearWatch`; switching away/closing the page stops the active component's watch. Browser throttling/suspension when backgrounded or the phone locks is platform-dependent; the app cannot guarantee continued capture. Closing/reloading also loses activeSession because it is memory-only. Sources: [`beacon-share-session.js`](../apps/resident-pwa/src/pages/beacon-share-session/beacon-share-session.js), [`beacon-home.js`](../apps/resident-pwa/src/pages/beacon-home/beacon-home.js), [`beacon.client.js`](../apps/resident-pwa/src/features/beacon/beacon.client.js).
- **Off-path:** only path mode with the toggle on is monitored. A fresh location with accuracy <50 m must remain more than 100 m from the route for 20 seconds to fire. Observations over 30 seconds apart reset evidence; returning within 100 m rearms after 30 seconds. Active-share UI polls the monitor every five seconds as well as evaluating on location changes. When triggered, it adds a system-card message to selected members' local chat arrays and updates the local banner; it does not deliver an alert to another device or send a push. Sources: [`off-path-monitor.js`](../apps/resident-pwa/src/features/beacon/off-path-monitor.js), [`beacon-share-session.js`](../apps/resident-pwa/src/pages/beacon-share-session/beacon-share-session.js), [`beacon.client.js`](../apps/resident-pwa/src/features/beacon/beacon.client.js).
- **Arrival/expiry:** arrival requires a path session set to “Until I arrive”, a fresh fix (<30 seconds old) with accuracy <50 m, and distance within 50 m of destination. Timer durations `30 min`, `1 hour`, and `2 hours` are client `setTimeout`s. `Until I stop` has no automatic timer. Timers and arrival logic are not server-side and may be delayed/suspended if the page is inactive. Sources: [`beacon-location.js`](../apps/resident-pwa/src/features/beacon/beacon-location.js), [`beacon.client.js`](../apps/resident-pwa/src/features/beacon/beacon.client.js), [`beacon-share-session.js`](../apps/resident-pwa/src/pages/beacon-share-session/beacon-share-session.js).
- **Route computation:** search/route requests use the `beacon-route` Edge Function; geocoder and routing URLs are environment-configured, with OSRM-compatible request/response shapes (geocoder `/search?format=jsonv2`, routing `/route/v1/{profile}/...`). Walking profile defaults to `foot`. The handler enforces 2–120 characters, up to five places, 100 m–10 km route length, 8-second upstream timeout, and max 500 output points; no request quota, cache, or provider-cost guard is implemented. Provider pricing/retention is unknown. Sources: [`beacon-route/handler.js`](../supabase/functions/beacon-route/handler.js), [`beacon-draw-path.js`](../apps/resident-pwa/src/pages/beacon-draw-path/beacon-draw-path.js).
- **Battery/data implications:** high-accuracy location is started on home entry, then active share maintains a position watch and 5-second status/off-path timer while open. This can consume battery and data; continuous background tracking is not implemented. Map tile and route/geocoder network requests have separate data/provider implications. No.** The location marker and alerts are local UI state, share member IDs are not resolved to accounts, and no app call writes/broadcasts location points. The route/geocoder and map-tile providers may receive route endpoints or map-tile requests, but those are not delivery to the selected person. ## 9. Concrete security and privacy risks (ranked)

These are code-grounded risks, not claims that an attacker has exploited staging.

1. **Critical safety reliance risk — UI implies sharing that does not happen.** The central feature says selected people receive live location and off-path alerts, but those are only local state; fresh accounts cannot populate a circle through the implemented search/invite flow. A resident may rely on protection that is not delivered. Sources: [`beacon-safety-notice.js`](../apps/resident-pwa/src/pages/beacon-safety-notice/beacon-safety-notice.js), [`beacon.client.js`](../apps/resident-pwa/src/features/beacon/beacon.client.js), [`beacon-find-contacts.js`](../apps/resident-pwa/src/pages/beacon-find-contacts/beacon-find-contacts.js).
2. **High privacy/consent risk — absolute location-retention promise is unsubstantiated.** The safety copy says no location history or server log; route calculation sends origin/destination to the configured routing service, place search sends the query to the geocoder, and map tiles disclose viewed geographic areas to a tile host. Provider logging/retention is not controlled in this repository, and consent is not captured per route/share. Sources: [`beacon-safety-notice.js`](../apps/resident-pwa/src/pages/beacon-safety-notice/beacon-safety-notice.js), [`beacon.client.js`](../apps/resident-pwa/src/features/beacon/beacon.client.js), [`beacon-route/handler.js`](../supabase/functions/beacon-route/handler.js), [`leaflet-map.js`](../apps/resident-pwa/src/features/beacon/leaflet-map.js).
3. **High sensitive-data-at-rest risk — browser text is plaintext.** Locally persisted names, member records, chat contents, and requests in localStorage, plus pending route coordinates in sessionStorage, are readable by same-origin scripts and remain in the browser until cleared/expired. No Beacon encryption-at-rest layer is used. Sources: [`beacon.client.js`](../apps/resident-pwa/src/features/beacon/beacon.client.js), [`docs/app-data-inventory.md`](./app-data-inventory.md).
4. **High contact privacy risk — selected third-party contact PII is retained in account tables.** Name/phone and normalized phone are stored for explicitly chosen/typed people. RLS restricts ordinary queries to the owner, but the feature has no deletion control in the contact list and no phone verification/consent from the person whose number is stored. Raw `phone` and normalized digits are both kept. Sources: [`0029_beacon_contacts.sql`](../supabase/migrations/0029_beacon_contacts.sql), [`beacon-contacts.js`](../packages/supabase-client/src/beacon-contacts.js), [`beacon-find-contacts.js`](../apps/resident-pwa/src/pages/beacon-find-contacts/beacon-find-contacts.js).
5. **High harassment/spoofing design risk if requests are wired as designed.** Current requests are local and cannot reach another user, but request objects are identified/matched by display name and contact phones are not verified. The current invite can launch an SMS to any typed number. Before remote matching is built, do not trust a name or an unverified phone as account identity; add rate limits, abuse/block/report controls, and recipient opt-in. Sources: [`beacon.client.js`](../apps/resident-pwa/src/features/beacon/beacon.client.js), [`beacon-find-contacts.js`](../apps/resident-pwa/src/pages/beacon-find-contacts/beacon-find-contacts.js), [`supabase/functions/beacon-block-report/`](../supabase/functions/beacon-block-report).
6. **Medium enumeration risk is prospective, not currently exposed by the live search.** Product copy promises lookup by name/number, and endpoint constants include resident/request endpoints, but actual `searchResidents()` returns `[]` and no phone/profile matching is performed. A future implementation that exposes existence on search needs explicit user opt-in, query throttling, and minimal responses. Sources: [`beacon.client.js`](../apps/resident-pwa/src/features/beacon/beacon.client.js), [`endpoints.js`](../packages/functions-client/src/endpoints.js), [`contacts-permission.js`](../apps/resident-pwa/src/pages/contacts-permission/contacts-permission.js).
7. **Medium historical-location exposure risk for the separate `wa_id` tables.** The staging snapshot recorded coordinates and session rows associated with `wa_id`; prior broad authenticated SELECT policies were later targeted for removal, and privilege hardening revokes client-role table grants. The current live policy state and row counts were not queried; service-role access remains a privileged path. Sources: [`docs/app-data-inventory.md`](./app-data-inventory.md), [`20260919000200_beacon_wa_id_policy_hardening.sql`](../supabase/migrations/20260919000200_beacon_wa_id_policy_hardening.sql), [`20261012000100_privilege_hardening.sql`](../supabase/migrations/20261012000100_privilege_hardening.sql).
8. **Medium operational/provider-abuse risk.** `beacon-route` is authenticated and validates input, but no application-level rate limiter/cache or provider-cost budget exists. If deployed with billable geocoder/routing services, a compromised account or high-volume caller may create provider load/cost. CORS allows `*`, but handler also requires a valid bearer user token. Sources: [`beacon-route/handler.js`](../supabase/functions/beacon-route/handler.js), [`20261012000200_report_rate_limit_rpc.sql`](../supabase/migrations/20261012000200_report_rate_limit_rpc.sql).
9. **Medium minors/POPIA governance risk.** No Beacon-specific age/guardian gate, granular consent record, documented recipient/retention policy, or remote stop/revocation protocol is present. Device contacts belong to third parties and precise location is sensitive; the current safety/permission copy overstates actual controls. This is a design/compliance gap, not a legal conclusion. Sources: [`router.js`](../apps/resident-pwa/src/router.js), [`beacon-safety-notice.js`](../apps/resident-pwa/src/pages/beacon-safety-notice/beacon-safety-notice.js), [`contacts-permission.js`](../apps/resident-pwa/src/pages/contacts-permission/contacts-permission.js), [`0029_beacon_contacts.sql`](../supabase/migrations/0029_beacon_contacts.sql).
10. **Low-to-medium resource risk.** High-accuracy location starts upon opening Beacon home and can use battery; disclosure is not limited to an intentional “start share” action. Active tracking is not guaranteed in background. Sources: [`beacon-home.js`](../apps/resident-pwa/src/pages/beacon-home/beacon-home.js), [`beacon-location.js`](../apps/resident-pwa/src/features/beacon/beacon-location.js).

### Product decisions needed before building the real feature
