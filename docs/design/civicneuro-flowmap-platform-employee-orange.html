Closed

The case is finalised and archived from active queues. Pin stays hidden, same as Resolved — Closed and Resolved are both "historical" for map and Report sheet tab purposes.

Reopened

A closed report was reopened — e.g. the issue recurred — and returns to Under Review. The pin switches back on automatically and the report moves back to the Active tab, same as any other non-resolved status.

Report lifecycle — Reopened · pin back on, returns to Active
Report sheet — map pin visibility (reference)
What "attended" means — the rule this section fills in

This wasn't defined anywhere before — the "Attended" stat sat on the Dashboard map screen showing 0 with nothing wired to it. The rule, now made explicit:

Status → Resolved or Closed
map_visible flips to false automatically. Pin disappears from the map. Report moves from the Report sheet's Active tab to its Historical tab.
Status → Reopened (or any other active state)
map_visible flips back to true automatically. Pin reappears. Report returns to Active.
Manual override, from the Historical tab
Select one or more historical reports → "Reactivate on map." Only map_visible changes — status is untouched, the report stays in Historical. Lets staff temporarily show old incidents on the map (e.g. reviewing a recurring problem) without re-opening the case.
Employee & Org Admin can toggle this — same scope as status updates. Platform roles: none.
Map pin visibility rule — governs both the lifecycle states above and the Report sheet tabs below

Effective 1 Aug 2026 · Applies to residents and organisation users
CivicNeuro collects the information needed to route and resolve civic reports: a resident's name and email, report descriptions, optional photo evidence, and location data (GPS coordinates or a manually described location).
Organisation users' data (name, email, role) is used to manage dashboard access and is scoped to the organisation they belong to.
Report data is shared only with the organisation a resident selects (or, for triage reports, the platform administrator). Internal notes added by organisation staff are never shown to residents.
Data is retained for as long as an account is active and for a reasonable period afterward to support audit and dispute resolution. Residents can request a copy of their data via Account actions → Download my data.

Effective 1 Aug 2026 · For organisation accounts
This agreement sets out how CivicNeuro (processor) handles personal data on behalf of a registered organisation (controller) for the purpose of receiving and managing civic reports.
Categories of data processed: resident contact details, report content and location, and evidence photos submitted against that organisation's categories.
CivicNeuro applies encryption in transit and at rest, role-scoped access control (see the RBAC matrix in the build spec), and audit logging on exports and status changes.
Sub-processors are limited to the hosting, object storage, and email providers listed in the build spec's stack. Data subjects (residents) may exercise access and deletion rights via their account.
